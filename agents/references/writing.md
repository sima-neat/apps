# Writing

The language rules for every text a person or agent reads in this repository: example
READMEs, `CONTRIBUTING.md`, `agents/`, `skills/`, the cheat sheet, and pull request
descriptions. A file with its own format, such as the README contract in `CONTRIBUTING.md`,
keeps that format and writes its sentences by these rules.

## Language

- Use the Core API's name for each thing, as the cheat sheet spells it, and keep that name.
  Explain a term at its first use when a reader outside the work may not know it.
- Write full sentences with their articles and verbs, never fragments.
- Give one action per sentence, with its condition first: "If the build fails, fix its first
  error."
- Use the active voice and name who acts: "The run drops the oldest frame".
- Use the plain, literal word: "use", "start", "because". Write "fails" for "falls over".
- Write no em dashes and no semicolons.
- Short means deleting sentences that change nothing the reader does. Keep every value,
  condition, exception, and failure.
- State each fact once. Other text links to it.
- Describe what the code does today, not how it got this way.

# SiMaSentry-Med — Offline / Air-Gapped

A zero-dependency, single-page web harness for medical and radiology AI, built for **air-gapped factory devices** with no internet access. It runs entirely against a **local Ollama** server and ships as four plain files — `index.html`, `style.css`, `app.js`, and this `README.md`. No CDN, no fonts, no analytics, no build step.

> ⚠ **Disclaimer.** Output is generated by an AI model and is **not a medical diagnosis**. Always consult a licensed physician for clinical decisions.

---

## Hard offline rules

The harness is built to obey four absolute rules so it can ship on factory devices that never see the internet:

1. **Zero external network requests.** No CDN. No Google Fonts, FontAwesome, Tailwind, Bootstrap, or any external asset. Nothing is fetched from the public internet at any time.
2. **Local styling & icons.** All CSS is hand-written in `style.css`. Every UI icon (mic, speaker, image-attach, settings gear, send, clear, close, attachment-X) is an inline `<svg>` in `index.html`. The favicon is an inline `data:image/svg+xml` URI.
3. **Strict-local TTS voices.** Browser text-to-speech is filtered to voices where `localService === true`, so Chrome's network-backed Google voices are never chosen — only OS-installed voices.
4. **Graceful STT offline handling.** Some browsers' speech-recognition engines need network access (Chrome/Edge use cloud STT). When that fails, the harness shows a clear, actionable message and lets the user fall back to keyboard input.

The default provider is **local Ollama** at `http://localhost:11434/v1/chat/completions`. OpenAI is an optional secondary provider for non-air-gapped contexts only.

## Air-gap audit

Verifying these claims is one `grep` away:

```bash
# Every script/style/font/url reference in the source tree.
# Should return only:  href="style.css", src="app.js", and a data:image/svg+xml favicon.
grep -nE 'src=|href=|@import|@font-face|url\(' health/index.html health/style.css health/app.js
```

The single outbound `fetch()` call in `app.js` targets `settings.baseUrl` — the chat endpoint configured in Settings (default: `http://localhost:11434/v1/chat/completions`). There are no other network calls. You can confirm this in any browser's DevTools → Network panel: while idle, zero requests; while sending, exactly one POST to the configured endpoint.

## Quick start (offline)

```bash
# from the project root
python3 -m http.server 8000 -d health
# then open http://localhost:8000
```

`localhost` counts as a secure context, so the microphone (where supported) and `speechSynthesis` work. Any other static-file server works too — there is nothing to build.

> Opening `index.html` directly with `file://` works for chat and TTS, but the **microphone is blocked on `file://`** by every modern browser. Use `localhost` for full functionality.

## Running with Ollama (primary path)

1. **Install Ollama** on the device: <https://ollama.com/download>. (Pre-stage the installer and model files on the air-gapped device — Ollama itself is the only binary you need.)

2. **Pull a model.** The default is `gemma3` (Google Gemma 3, multimodal at 4B+):
   ```bash
   ollama pull gemma3                  # default — multimodal at 4B/12B/27B variants
   ollama pull llava                   # alternative vision model
   ollama pull llama3.2-vision         # alternative vision model
   ollama pull qwen2.5-vl              # alternative vision model
   ollama pull llama3.2                # text-only fallback
   ```
   > Note: `gemma3:1b` is text-only. `gemma3` (default tag), `gemma3:4b`, `gemma3:12b`, and `gemma3:27b` are multimodal and accept medical-image inputs.

3. **Start the daemon** (auto-starts on macOS via the menu bar app, or run `ollama serve`).

4. **The harness already points** at `http://localhost:11434/v1/chat/completions` with model `gemma3` — open it in a browser and you can begin.

### CORS configuration (required when serving from a different origin)

When the harness is loaded from `http://localhost:8000` and Ollama runs on `http://localhost:11434`, the browser blocks the request unless Ollama explicitly allows the origin.

**macOS:**
```bash
launchctl setenv OLLAMA_ORIGINS "*"
# Then restart Ollama (quit from menu bar, re-open).
```

**Linux (systemd):**
```bash
sudo systemctl edit ollama.service
# Add under [Service]:
#   Environment="OLLAMA_ORIGINS=*"
sudo systemctl daemon-reload
sudo systemctl restart ollama
```

**Windows (PowerShell, current session):**
```powershell
$env:OLLAMA_ORIGINS = "*"
ollama serve
```

For LAN access (e.g. running Ollama on a separate workstation):
```bash
launchctl setenv OLLAMA_HOST "0.0.0.0"
```

> 🔒 `OLLAMA_ORIGINS=*` allows any origin on this machine to reach your local Ollama. For multi-user devices, restrict it to a single origin like `http://localhost:8000`.

## Configuration

Open the **⚙ Settings** drawer (top-right) to set:

| Field | Notes |
|---|---|
| **Provider** | `Ollama (local)` (default) or `OpenAI` (online only) |
| **Base URL** | Full chat endpoint. Auto-fills when you toggle the provider. |
| **API Key** | OpenAI only. Stored in `localStorage` on this device. Hidden when Ollama is selected. |
| **Model** | Free text. Default `gemma3`. Examples: `gemma3`, `gemma3:12b`, `llava`, `llama3.2-vision`, `qwen2.5-vl`, `gpt-4o`. |
| **Language** | BCP-47 locale (e.g. `en-US`, `es-ES`, `zh-CN`). Drives speech recognition and TTS voice selection. |
| **System Prompt** | The instruction sent as `messages[0].role = "system"`. Defaults to a radiology + multilingual prompt. **Reset to default** restores it. |
| **Auto-read** | If on, the assistant's full response is read aloud after each turn. |

Settings are saved to `localStorage` under the key `medical-ai-harness:settings`.

## Deep-linking with URL parameters

Pre-configure the harness via the query string. Recognized parameters:

| Param | Type | Purpose |
|---|---|---|
| `provider` | `openai` \| `ollama` | Selects provider; auto-fills `baseUrl` and `model` if those are not also set. |
| `base_url` (alias `baseUrl`) | URL | Full chat endpoint. |
| `api_key` (alias `apiKey`) | string | OpenAI API key. **Stripped from the URL bar after loading** (it ends up in `localStorage`). |
| `model` | string | Model name. |
| `lang` (alias `language`) | BCP-47 | e.g. `es-ES`, `zh-CN`, `ja-JP`. |
| `system_prompt` (alias `systemPrompt`) | URL-encoded string | Override the system prompt. |
| `auto_read` (alias `autoRead`) | `0` \| `1` \| `true` \| `false` | Initial auto-TTS state. |
| `mode` | `medical` | Locks the system prompt back to the radiology default and applies the clinical white/blue theme (`body[data-mode="medical"]`). |

**Precedence on load:** defaults → `localStorage` → URL params (URL always wins). The merged result is then persisted, so URL params "stick" for the next visit.

### Examples (offline / Ollama-first)

Medical/radiology mode, default Ollama + Gemma 3 + clinical theme:
```
http://localhost:8000/?mode=medical&provider=ollama&model=gemma3
```

Local Ollama with the default `gemma3` model, Spanish UI:
```
http://localhost:8000/?provider=ollama&model=gemma3&lang=es-ES
```

Larger Gemma 3 variant (12B) on the LAN, Mandarin:
```
http://localhost:8000/?provider=ollama&base_url=http://192.168.1.10:11434/v1/chat/completions&model=gemma3:12b&lang=zh-CN
```

Custom system-prompt override (URL-encode the text):
```
http://localhost:8000/?provider=ollama&model=gemma3&system_prompt=You%20are%20a%20cardiology%20specialist...
```

### Example (online / OpenAI — only on devices with internet access)

```
http://localhost:8000/?provider=openai&model=gpt-4o&lang=en-US&api_key=sk-...
```

> ⚠ **Security note.** Putting `api_key` in a URL means it can leak via browser history and HTTP `Referer` headers. The harness mitigates this by removing `api_key` from the address bar immediately after applying it. For air-gapped Ollama, no key is needed.

## Voice support

### Browser STT matrix (for offline / air-gapped use)

| Browser | STT engine | Works air-gapped? |
|---|---|---|
| **Safari iOS 14+ / macOS 14+** | On-device | ✅ Yes |
| **Chrome / Edge** | Google / Microsoft cloud | ❌ No — harness shows a clear message and falls back to keyboard input |
| **Firefox** | Off by default; requires `media.webspeech.recognition.enable` flag | ⚠ Implementation-dependent |

When STT fails because of a missing network, the harness specifically catches the `network` and `service-not-allowed` error codes and shows:

> *"Speech recognition needs the browser's online engine, which is unavailable on this air-gapped device. Use the keyboard, or a browser with on-device STT (Safari iOS 14+ / macOS 14+)."*

The microphone button is also automatically disabled if `SpeechRecognition` is missing entirely (e.g., older Firefox without the flag).

### Strict-local TTS voices

The harness filters `speechSynthesis.getVoices()` to voices where `localService === true`. This excludes Chrome's network-backed Google voices and uses only OS-installed voices. The picker tries:

1. Exact lang match (e.g., `es-ES`).
2. Primary subtag match (e.g., `es-MX`, `es-AR`).
3. Browser's default voice.
4. First available local voice.

If no exact local voice is found for the chosen language, the status bar shows a non-fatal note like *"No exact local voice for `es-ES`; using Helena (`en-US`)."* If no local voice exists at all, an error message explains how to install OS voices.

> **macOS:** System Settings → Accessibility → Spoken Content → System Voice → Manage Voices. Download voices for the languages you need; they are then available offline.
> **Windows:** Settings → Time & Language → Language & region → Add language → Speech.
> **Linux:** Install `speech-dispatcher` and a voice package (e.g., `espeak-ng`, `mbrola-*`).

TTS speaks only the **completed** assistant turn, not streaming tokens, to avoid choppy speech.

## Diagnostic Workbench (Tab 2)

The **Workbench** tab is purpose-built for radiology — a high-resolution viewer for X-rays, MRIs, CTs, and other medical images with **interactive point analysis**.

**Workflow:**
1. Upload a scan (composer 🖼 button on the Chat tab, or **Choose image** on the Workbench).
2. Switch to **Workbench**. Hover the image — pixel coordinates are shown in the toolbar.
3. **Click any point** on the scan. A numbered marker appears (pulsing dashed circle while pending), and the harness sends a coordinate-anchored prompt to the VLM:
   > *Analyze the area around these specific coordinates [x=412, y=287] on the attached medical image (image dimensions 1024×768 pixels) for potential medical anomalies. Identify the anatomy at this location if visible, describe any findings objectively, and include the standard medical disclaimer.*
4. As the response streams in, it renders live in the **Findings** sidebar (and in the Chat tab). When the analysis completes, the marker becomes solid and the finding is numbered to match.
5. **Click any marker or finding** to highlight the pair. **Clear markers** wipes the overlay; the underlying image stays.

**Visual layer:**
- The image and an SVG overlay share an aspect-ratio-locked frame, so markers stay anatomically aligned at any zoom or window size.
- Marker coordinates use the image's **natural** pixel space (via the SVG `viewBox`), with `vector-effect: non-scaling-stroke` so the ring stays visually consistent regardless of display scaling.
- The overlay is **non-destructive** — it never touches the underlying image bytes.

**System prompt (default):**
> *You are an expert Medical AI and Radiologist. Provide descriptive, objective findings based on the visual data. Always include a standard medical disclaimer. Respond in the same language detected in the user's prompt.*

Override it in Settings → System Prompt, or pass `?system_prompt=…` in the URL. `?mode=medical` snaps it back to this default and applies the clinical white/blue theme.

**Robustness:**
- Stop tokens like `<end_of_turn>` (Gemma), `<|im_end|>` (ChatML), `<|eot_id|>` (Llama 3), `</s>` (Mistral) are filtered from streamed content even when a server's `eos_token_id` is misconfigured. The filter holds back a small tail buffer so tokens split across two SSE chunks are caught.
- Conversation history is auto-sanitized to strict user/assistant alternation before each request, so chat templates that enforce this (Gemma 3) never see consecutive same-role messages.

## Performance metrics (TTFT / TPS)

Every completed assistant turn shows a metrics line under the bubble — useful for benchmarking model performance on a given factory device.

```
TTFT 412 ms · TPS 24.3 tok/s · Out 287 tok · In 168 tok · Total 12.18 s
```

| Metric | Definition |
|---|---|
| **TTFT** | **Time to first token** — wall-clock time from `fetch()` dispatch to the first SSE chunk arriving. |
| **TPS** | **Tokens per second** — output tokens divided by generation time (from first token to last). Excludes TTFT. |
| **Out** | Output tokens. Authoritative count when the server returns `usage` (OpenAI / Ollama with `stream_options.include_usage`); a `~`-prefixed estimate (chars ÷ 4) otherwise. |
| **In** | Prompt tokens, only shown when the server reports them. |
| **Total** | Wall-clock time for the entire request, TTFT + generation. |

The harness sets `stream_options: { include_usage: true }` in every payload so OpenAI-compatible servers return token counts; servers that don't honor the flag fall back to the character estimate (marked with `~`). Hover over each metric to see the precise definition.

## Vision support

Attach an image with the 🖼 button. The harness:

1. Reads it via `FileReader.readAsDataURL` to a `data:image/...;base64,...` URI.
2. Downscales any image larger than ~4 MB to a max edge of 1536 px (rendered to JPEG at 0.9 quality) using an offscreen `<canvas>`. Cap is 10 MB.
3. Sends it inside the standard OpenAI vision payload:
   ```json
   {
     "role": "user",
     "content": [
       { "type": "text", "text": "Findings?" },
       { "type": "image_url", "image_url": { "url": "data:image/png;base64,..." } }
     ]
   }
   ```

**Vision-capable models tested with Ollama:** `gemma3` (4B, 12B, 27B), `llava`, `llama3.2-vision`, `qwen2.5-vl`. The `gemma3:1b` and text-only models like `llama3.2`, `gpt-3.5-turbo` reject vision payloads.

For non-air-gapped environments you can switch the provider to **OpenAI** in Settings, paste an API key, and use models like `gpt-4o` or `gpt-4o-mini`. This is intentionally a secondary path. On factory devices without internet, leave the provider on Ollama.

## Privacy

- **Settings** (including any API key) live in your browser's `localStorage` for this origin. Never transmitted anywhere except the chat endpoint.
- **Chat history** is in-memory only — refreshing the page discards it.
- **Image data** is sent directly to whichever provider you have configured. On Ollama, that means it never leaves the device.
- **Zero third-party telemetry, fonts, analytics, or scripts.** Verified by the audit recipe above.

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| `Network error reaching http://localhost:11434/...` | CORS — set `OLLAMA_ORIGINS=*` (see above) and restart Ollama. |
| `404` from Ollama | Model not pulled: `ollama pull gemma3`, or wrong path — the harness expects `/v1/chat/completions`. |
| `401 Authentication failed` | Wrong or missing OpenAI API key. Open Settings. |
| Status bar: *"Speech recognition needs the browser's online engine…"* | Working as intended on air-gapped devices in Chrome/Edge. Type instead, or switch to Safari (macOS/iOS). |
| Status bar: *"No exact local voice for es-ES…"* | OS doesn't have a Spanish voice installed. Install via system settings (see TTS section). |
| Status bar: *"No local voice installed; install an OS voice for TTS."* | Strict-local filter found zero candidates. Install at least one system voice. |
| Microphone button disabled | Browser doesn't expose `SpeechRecognition`, or you're on `file://`. Use Chrome/Edge/Safari over `localhost`. |
| Image upload fails with "too large" | Try a smaller file or screenshot a region. Cap is 10 MB; >4 MB images are auto-downscaled to 1536 px. |
| Vision response is "I cannot see images" | The configured model is text-only. Switch to `gemma3` (4B+), `llava`, etc. |

## Architecture

A single classic `<script src="app.js">` (no ES modules) so the file works on `file://` as well as over HTTP. Six classes inside one IIFE:

| Class | Role |
|---|---|
| `SettingsStore` | Defaults → `localStorage` → URL params merge; change-event dispatch; `api_key` URL stripping. |
| `ChatClient` | `fetch` wrapper, builds OpenAI-style payloads (Ollama is wire-compatible at `/v1/chat/completions`), parses SSE, surfaces `ApiError`. |
| `ImageHandler` | `FileReader` → data URI; canvas downscale for large images. |
| `VoiceController` | `SpeechRecognition` (interim results, language-aware) + `speechSynthesis` with **strict `localService === true` voice filtering**. |
| `ChatRenderer` | Message bubbles, attachments, safe lightweight markdown (bold / italic / code / lists / fenced blocks) — never `innerHTML` with model output. |
| `App` | Bootstrap, DOM bindings, conversation state, send/receive/speak orchestration, friendly error mapping. |

Conversation history lives in memory only (cleared on refresh and on **Clear**).
